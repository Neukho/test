# 일러스트 제작 계획 및 일정 (0단계)

> 이 문서는 **계획**입니다. 도구별 구체 프롬프트·파라미터는 3단계(하울 수직 슬라이스)에서 캐릭터별 키트로 제공합니다.
> AI 도구의 모델명·약관·기능은 자주 바뀌므로, **착수 전 공식 약관/문서를 다시 확인**하세요(§8).

---

## 1. 도구 조합 추천

| 도구 | 강점 | 약점 | 이 프로젝트에서의 역할 |
|---|---|---|---|
| **Stable Diffusion (ComfyUI)** | 캐릭터 LoRA, ControlNet, IP-Adapter, 인페인팅 등 **일관성 제어 최고**. 로컬 실행 → 이력 관리 용이 | 설정·학습 난도, GPU 필요 | **주력**: 스탠딩·CG·표정 교체 |
| **NovelAI** | 애니풍 품질이 빠르게 안정, 레퍼런스 기반 기능, 인페인팅 간편 | 세부 제어 한계, 약관/기능 변경 가능 | 보조: 콘셉트 탐색, 빠른 러프, 표정 인페인팅 |
| **Midjourney** | 배경·소품·분위기 컷 품질, 스타일 레퍼런스(`--sref`) | 캐릭터 정확도·인페인팅 한계, 약관 확인 필요 | 배경(거리·가게 외관)·타이틀 아트·음식 아이콘 시도 |

**추천 조합**: **ComfyUI(주력) + NovelAI(러프/표정 보정) + Midjourney(배경·음식)**
- 이유: 6명이 ‘어떤 장면에서도 같은 얼굴/체형’이어야 하므로 **캐릭터별 LoRA + 레퍼런스 고정**이 가능한 ComfyUI가 핵심.
- 대안(리소스가 적을 경우): NovelAI 단일 + 수작업 보정. 일관성 한계는 인페인팅과 레퍼런스로 완화.
- 모델/체크포인트 라이선스: **상업 이용 가능 여부를 모델 카드에서 확인**(§8).

### ⚠ 사용자 환경 반영: 로컬 GPU 없음 (2026-10-03 결정)

로컬 ComfyUI 실행이 불가능하므로 **조합을 아래와 같이 조정**합니다. (위 표의 ‘주력=ComfyUI’는 클라우드 GPU를 쓸 때만 유효)

| 방식 | 비용 구조 | 일관성 | 추천도 |
|---|---|---|---|
| **A. NovelAI 중심(구독)** + Midjourney(배경·음식) | 월 구독 | 레퍼런스 기능 + 인페인팅 + 프롬프트 고정. LoRA 학습 불가 → 일관성은 **캐릭터 시트 레퍼런스 + 수작업 보정** | **기본안(추천)** — 설정 부담이 가장 적음 |
| B. 클라우드 GPU에서 ComfyUI(시간 단위 대여) | 사용 시간만큼 | LoRA 학습·ControlNet 가능 → **가장 높은 일관성** | 캐릭터 6명 LoRA가 필요해지는 3~4단계 후반에 **필요할 때만** 대여 |
| C. 외주(일부 핵심 컷) | 건당 | 최고 품질 | 타이틀·핵심 CG 일부만 선택적 |

**진행 순서 제안**
1. 3단계(하울): **A**로 캐릭터 시트와 스탠딩 3의상·표정 6종을 제작해 일관성이 충분한지 평가.
2. 얼굴·체형이 장면마다 흔들리면 **B**로 하울 LoRA 1개를 시범 학습(학습 이미지는 본인이 생성한 시트만 사용) → 효과가 크면 나머지 5명 확장.
3. 표정은 얼굴 레이어 분리(바디 1장 + 얼굴 6장)로 해결하므로 **얼굴 인페인팅 반복 횟수가 적다** — GPU 없는 환경에서도 가능한 이유.

> 약관·가격·기능은 수시로 바뀌므로 구독 전 공식 페이지에서 상업 이용 조건을 확인하세요(§8.1).

### 일관성 유지 방법 비교

| 방법 | 일관성 | 난도 | 비고 |
|---|---|---|---|
| 캐릭터 LoRA(학습) | 매우 높음 | 높음 | 학습용 이미지 20~40장 필요 → **캐릭터 시트에서 생성 후 큐레이션** |
| IP-Adapter / 레퍼런스 | 중~높음 | 중 | 학습 없이 시작 가능, 의상 변형엔 한계 |
| 시드 고정 + 마스터 프롬프트 | 낮음~중 | 낮음 | 보조 수단 |
| Vibe/Style 레퍼런스(NovelAI/MJ) | 중 | 낮음 | 화풍 통일에 유리 |
| 인페인팅(얼굴/손) | 보정용 | 중 | 표정 교체·결함 수정 |

권장 절차: ① 캐릭터 시트(정면/측면/후면) 생성 → ② 최적 컷 큐레이션 → ③ LoRA 학습 → ④ 이후 모든 컷은 LoRA + 레퍼런스 + 인페인팅.

## 7. 플레이스홀더(코드 생성) 계획

- 에디터 메뉴 `MorpheHouse/Art/Generate Placeholders`: 단색 실루엣 PNG를 **최종 파일명 그대로** 생성(캐릭터별 색상 코드 + 이름 라벨).
- 최종 일러스트를 **같은 파일명으로 덮어쓰면** 별도 작업 없이 반영. 생성기는 이미 존재하는 파일을 덮어쓰지 않음(실제 에셋 보호).
- 목적: 일러스트 없이도 하루 사이클·대화·CG 표시·저장 등 **모든 시스템 테스트**.

## 8. 권리·정책 점검표

### 8.1 AI 도구/모델 약관
- [ ] 사용하는 **도구의 상업적 이용 조건**(구독 등급, 출력물 권리 귀속) 확인
- [ ] 체크포인트·LoRA·업스케일 모델의 **라이선스(상업 가능 여부, 출처 표기 의무)** 확인
- [ ] 학습 데이터로 **타인의 저작물/실존 작가 작품을 사용하지 않음**(LoRA 학습 이미지는 **본인이 생성한 캐릭터 시트만** 사용)
- [ ] 약관 변경 대비: 확인 날짜와 URL을 기록

### 8.2 디자인 규칙
- [ ] 실존 작가 이름/화풍을 프롬프트에 **직접 지정하지 않음**
- [ ] 기존 캐릭터·실존 인물을 연상시키는 디자인 금지(유사도 검토)
- [ ] 성인 외형 고정(미성년 외형 금지)

### 8.3 배포 플랫폼
- [ ] **Steam**: AI 생성물 사용 여부를 상점 페이지 설문에서 **공개**(정책 최신본 확인)
- [ ] **itch.io**: AI 사용 태그/공개 요건 확인
- [ ] 스토어 페이지에 ‘AI 사용 범위’(일러스트 보조 등) 설명문 준비
