# 루트 구조 v0.3 — 개별 로맨스 + 다자(공동) 엔딩

> 사용자 결정(2026-10-03): 각 인물을 **개별 로맨스 스토리로 하나씩 공략**, **하렘(다자) 엔딩도 가능**. 일러스트는 사용자가 직접 제작해 삽입.
> 이 문서는 시나리오 작가·프로그래머가 따르는 **공통 계약**입니다.

## 1. 구조 개요

| 구분 | 내용 |
|---|---|
| 개별 루트 | 6명 각각 이벤트 1~5단계 + 엔딩 3종(노멀·굿·트루). 서로 독립된 감정선, 동등한 분량 |
| 루트 확정 | 7장. **1명(단독)** 또는 **2~3명(공동)** 을 선택. 선택하지 않은 인물은 ‘지지자’로 성장 정지(호감 감쇠 면제) |
| 공동 루트(다자) | 2인 또는 3인. **전원이 서로 알고 동의하는 관계**로만 서술 (비밀·기만·양다리 서사 금지) |
| 커뮤니티 엔딩 | 루트 미확정 또는 조건 미달: 모두와 함께하는 달빛 모퉁이(연애 아님) |

## 2. 다자 엔딩 설계 (시뮬레이션 근거)

300회 몬테카를로(노멀, 앞 k명(하울·요한·범준)에게 밤 행동의 f를 균등 분배, 기준 플레이어 = 대화 선택지 무작위·동의 장면은 승낙, `python3 tools/simulate_balance.py --runs 300 --group 2|3`). 단독 곡선은 그대로 두고 **다자 전용 파라미터**만 조정했다(2026-10-03):

| 그룹 | 확정 최소(구성원 전원) | 엔딩 조건(전원) | 확정 뒤 증가 배율 | f=60% | f=80% | f=100% | 숙련 f=60/80/100% |
|---|---|---|---|---|---|---|---|
| 2인 | 호감 50 / 신뢰 7 | 호감 72 / 신뢰 24 / 이벤트 3 | x1.0 | 2% | 9% | **57%** | 42 / 82 / 99% |
| 3인 | 호감 50 / 신뢰 7 | 호감 65 / 신뢰 14 / 이벤트 2 | x1.7 | 1% | 12% | **32%** | 14 / 28 / 57% |

- 데이터: `params.csv` `group_lock_min_aff/trust`(2~3명 확정 최소, 단독은 60/20 고정), `group_gain_mult_2/3`(확정 뒤 구성원 증가 배율), `endings.csv` `harem_duo`/`harem_trio`. 코드는 `RomanceService.CheckGroupLock`·`GroupLockMinAff/Trust`, 거절 문구는 `NightRomanceActions.LockRefusalText(reason, memberCount)`(묶음 크기에 맞는 기준 표시), `RouteLockOptions.Eligible` 은 단독 또는 공동 기준 중 하나라도 충족이면 true(`SingleEligible` 로 구분).
- C# 실제 대본 봇(`qa_hunt play`, QA_FOCUS=1, 60회, 무작위 선택·동의 승낙, f=100%): Normal 2인 53% / 3인 27%, Story 77% / 35%, Hard 30% / 13%; f=60% 에서는 Normal 3인 2%. 스마트(경로 계획) 봇은 모든 난이도에서 harem 엔딩에 도달.
- 이전 수치(2인 85/92/97, 3인 44/70/85 → QA 직후 6% / 0%)는 폐기. 단독 곡선(docs/03)은 변하지 않았다.
- 굿 기준을 그대로 쓰면 3인은 사실상 불가능 → **다자 전용 기준**을 `balance/endings.csv` 의 `harem_duo`, `harem_trio` 로 분리.
- 3인 루트는 밤 행동 90% 이상을 3명에 쏟아야 하는 **의도적 고난도**(노멀 기준 70%).
- 필수: 각 구성원과 **동의 이벤트**(`<Char>_Harem_Consent`) 완료 → 플래그 `harem_ok_<char>`.
- 구성원 중 한 명이라도 조건 미달이면: 조건을 충족한 구성원 중 호감이 가장 높은 인물의 **노멀 엔딩**이 아니라 **커뮤니티 엔딩**으로 간다(관계의 불균형 방지).
- 연애 상한: 그룹 최대 3명.

## 3. 다자 서사 가드레일 (작가 필독)

1. 모든 구성원은 성인이며 **자발적 동의**를 말과 행동으로 확인한다. 한쪽이 마지못해 받아들이는 구도 금지.
2. ‘독점 욕망’을 로맨스로 미화하는 서술 금지. 질투는 존중받는 감정으로 다루되 통제·집착 행동으로 이어지지 않는다.
3. 각자의 가치관이 흔들리지 않는다: 하울(신뢰), 요한(진심), 범준(의지), 하루(성장), 곰석(유산), 나비(자유) — **다자 관계 안에서도 자기 키워드를 지킨다**. (예: 나비는 ‘자유’를 보장받는 조건으로 동의)
4. 서로 호감이 없는 두 인물을 억지로 묶지 않는다. 구성원 간 관계(친구·동료)를 `Harem_Table` 에서 먼저 쌓는다.
5. 수위: 암시까지(키스·포옹·페이드 아웃). 노골적 묘사 없음.

## 5. 일러스트(사용자 제작) 인계 방식

일러스트는 사용자가 직접 만들어 넣는다. 제가 제공하는 것은 프롬프트가 아니라 **제작 요청서**입니다.
- 각 장면의 CG ID, 파일명(`CG_<Char>_E<N>.png`), 구도·조명·감정 지문, 등장 인물·소품·배경, 해당 장면의 대사 위치.
- 스탠딩: 바디 + 얼굴 레이어 규격(`02_Art_Plan.md §6`), 의상 3벌, 표정 6종.
- 파일명만 맞추면 코드 수정 없이 반영(`ArtLoader` 폴백 구조).
- 작가 에이전트는 시나리오의 `<<show_cg ID>>` 마다 장면 지문을 **`<Char>_art_requests.md`** 로 남긴다.
